# 技術構成と実行時の前提

## 技術構成

| 層 | 使用技術・役割 |
| --- | --- |
| 画面 | GAS HtmlService、HTML/CSS、JavaScript |
| サーバー | Google Apps Script（V8） |
| データ保存 | Googleスプレッドシート |
| 外部連携 | freee人事労務 public APIによる従業員・勤務情報の取得 |
| 自動テスト | Node.js標準のfs・path・vmなど。GASやDOMは必要な範囲を模擬 |

`web.gs`が画面を切り替え、各HTML画面から`google.script.run`でサーバー関数を呼びます。技能は`meister.gs`、勤務は`shift.gs`、希望は`shift_wish.gs`・`employee_shift_wish.gs`、成立判定は`shift_judge.gs`が主に担当します。

`attendance_legacy.gs`は現行画面から未使用の旧処理を保持するファイルです。現行の実装済み機能の説明には含めていません。

## ローカルでの検証

Node.js 22以上で、リポジトリのルートから実行します。

```sh
npm test
```

アプリの実画面はGAS上で実行します。公開リポジトリには実データと接続先を含めていないため、cloneだけではアプリを起動できません。

## GAS実行環境

専用スプレッドシートに紐づくApps Scriptプロジェクトと、freeeの開発用事業所が必要です。`src/`のファイル名を維持してGASへ配置します。HTMLのincludeがファイル名に依存しているため、個別ファイルの名前を変えないでください。

主に使用するシートは「マイスターマスタ」「シフト予定」「希望シフト」です。既存環境のコピーではなく新規に構築する場合、各シートの列・型をコードと一致させる必要があります。希望シフトは初回アクセス時のシート自動作成に対応していますが、すべての環境を自動構築するセットアップ機能はありません。

公開版`config.gs`は空のトークンと事業所ID `0`を持つひな形です。実値は本人のGASエディタにのみ設定します。このファイルを再配置すると設定が空に戻るため、本人が設定し直す必要があります。claspを使う場合も、`.clasp.json`は各自の環境にだけ置き、Gitには追加しません。

## 現行版の制約

- 個人認証・店主専用の権限管理は未実装。
- トークンの自動更新は未実装。
- `getEmployee()`には取得年月の固定値が残る。
- 祝日などの営業日設定は対象年を確認する必要がある。
- UserPropertiesによる選択状態と、実際のブラウザ・GASの動作は実機確認が必要。

デモは架空データと専用の開発環境で確認します。
