# 企画概要

## 対象ユーザーと課題

対象はラーメン店の店主です。勤務人数だけでなく、ホール・セット・仕込み・麺上げなどの持ち場を担当できる組み合わせを確認する必要があります。特定の主力が不在でも営業を成立させる配置と、担当者を増やすための育成判断を支援します。

## 主な利用の流れ

1. 従業員ごとのマイスター（持ち場別技能）を管理する。
2. 従業員が前半・後半ごとの希望を複数日まとめて提出する。
3. 店主が提出状況を確認し、希望を見ながら勤務を登録する。
4. 1時間枠ごとに必要人数と持ち場が成立するか確認する。
5. 不足する持ち場、一人依存、育成候補を見て次の配置・育成を考える。

## 設計で意識したこと

- 希望シフトと登録済みの勤務を別データとして管理する。希望だけではシフト成立判定に加えない。
- 持ち場の成立判定では、同じ人を同時に複数の担当として数えない。
- 従業員の希望は店主画面から変更・削除せず、店主が登録する勤務と区別する。
- 翌日まで続く営業時間を、暦日と営業日を区別して扱う。
- 不成立の詳細には不足情報を示し、成立時には担当候補と予備人数を示す。
- 合計スコアによる個人の序列化を避け、持ち場を満たせるかを判断の中心にする。

## 現在の範囲と検討事項

現在はデモ用アプリです。従業員選択は認証ではなく、店主専用のアクセス制限も未実装です。

今後の候補は、個人ログイン、店主だけの編集権限、技能状況の読み取り専用共有、確定シフトの公開と閲覧、通知、育成候補の指標の再検討です。優先順位と実装範囲は、本人の操作経験を確認してから決めます。
